# DB 스키마 (SQLite 파일 1개: data/database.sqlite — 커밋 금지)

## 테이블: expenses
| 컬럼 | 타입 | 제약 | 설명 |
|------|------|------|------|
| id | INTEGER | PK AUTOINCREMENT | 고유 ID |
| store_name | TEXT | NOT NULL | 상호명 (API: storeName) |
| date | TEXT | NOT NULL | YYYY-MM-DD 문자열 그대로 |
| amount | INTEGER | NOT NULL | 원 단위 정수 |
| category | TEXT | NOT NULL | 6종 코드 |
| transaction_type | TEXT | NOT NULL | EXPENSE / TRANSFER / INCOME |
| defendant | TEXT | NOT NULL DEFAULT '' | 피고인 이름 (API: defendant, 10자 이내) |
| memo | TEXT | NOT NULL DEFAULT '' | 미분류 내역 정리용 메모, 입력 쪽 (API: memo, 10자 이내) |
| plea | TEXT | NOT NULL DEFAULT '' | 피고인 변론, 판결 쪽 — N빵 정상참작 근거 (API: plea, 200자 이내) |
| needs_review | INTEGER | NOT NULL DEFAULT 0 | 1이면 미분류 (API: needsReview, boolean) |
| created_at | TEXT | NOT NULL | 생성 시각 |
| updated_at | TEXT | NOT NULL | 수정 시각 |

## 규칙
- DB=snake_case, API=camelCase — 변환은 백엔드에서만 (프론트는 DB 컬럼명 모름)
- 테이블 1개로 MVP 전체 커버 (users/verdicts 없음 — 로그인 없음, 판결은 매번 계산)
- CREATE TABLE IF NOT EXISTS — 재시작 시 데이터 보존
- 컬럼 추가는 db.py의 `_migrate()`가 ALTER TABLE로 처리한다. 운영 중인 DB(배포 서버)를
  지우지 않고 확장하기 위함이며, 기존 행의 빈 defendant는 기본 피고인으로 채워진다.
- needs_review는 SQLite에 boolean이 없어 INTEGER(0/1)로 저장하고, API 응답에서만 boolean으로 바꾼다.
