# 요구사항 명세 (출처: 팀 설계·작업 명세서 → 상세는 docs/05·06)

## P0 — 오늘 반드시 (절대 제거 금지)
1. 소비 내역(상호명/날짜/금액/카테고리/거래유형)을 입력하면 DB에 저장된다
1-1. **지출내역 파일(엑셀·CSV·텍스트 PDF)을 업로드하면 거래를 뽑아 저장한다** — 주 입력 경로.
     원시 추출(pandas·pdfplumber) → Bedrock이 표준 JSON으로 정규화·카테고리 분류.
     Bedrock 실패 시 규칙 기반 폴백으로 계속 동작한다. 이체는 자동으로 TRANSFER 처리.
2. 이체(TRANSFER)를 입력하면 저장은 되지만 모든 분석에서 제외된다
3. 월을 선택하면 그 달의 소비 내역만 목록으로 보인다
4. 소비 내역을 수정하면 목록과 분석 결과에 반영된다
5. 소비 내역을 삭제하면 목록과 분석 결과에서 사라진다
6. 분석을 실행하면 총지출·결제 횟수·평균·소액 건수·카테고리별 통계가 나온다
7. 분석하면 소비 유형이 정확히 하나 판정된다 (룰 기반, 7종)
8. 판결문이 나온다 — 죄명/증거/판결/이유(Bedrock 생성)/형량
9. 소비 유형 배너를 클릭하면 MZ 리액션 메시지가 뜬다
10. EC2(http://18.135.105.80:8501)에서 실제 접속된다

## P1 — 시간 남으면
1. 빈 데이터 안내 ("판결을 원하시면 소비 내역부터 제출하세요 👨‍⚖️")
2. 삭제 확인 모달
3. 재미있는 로딩 문구 ("법정 개정 중...")
4. 서비스 톤 에러 문구
5. 카테고리별 색상

## P2 — 충분하면
검색 / 금액 정렬 / 카테고리 필터 / 판결문 문구 5개+ / MZ 15~20개 / 결과 화면 애니메이션

## 제외 — 안 만드는 것 (합의)
OCR / 로그인·회원가입 / 금융 계좌 연동 / AI 학습 / 복잡한 예산 추천
**스캔본(이미지) PDF** — 텍스트가 없는 PDF는 비전 처리가 필요해 이번 범위에서 제외.
업로드 시 안내 메시지를 띄우고 수동 입력으로 유도한다. (영수증 사진 인식도 동일하게 제외)
