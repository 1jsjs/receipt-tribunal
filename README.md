# ⚖️ 영수증 소비 재판소

> **"한 달치 소비 내역을 제출하면 통장이 나를 고소한다."**

자취생의 한 달 소비를 분석해 **판결문**(죄명·증거·판결·이유·형량)과 **소비 유형**을 선고하는 웹 서비스.
분석 결과를 법원 판결문으로 보여주고, 유형 배너를 누르면 MZ 리액션이 튀어나옵니다.

_2026 호남권 SW중심대학 AWS Kiro 해커톤 — 7조_

## 사용자 경험

```
소비 입력 → "어? 내가 배달을 이렇게 많이 시켰어?" → 소비 재판
→ "냉장고 유기죄?!" → 냉장고보다 배달앱형 ㅋㅋ → [배너 클릭]
→ "ㅋㅋ루삥뽕 너 오늘도 배달 시켰지?" → ㅋㅋㅋㅋ
```

## 기술 스택

| 레이어 | 기술 |
|---|---|
| Frontend | 순수 HTML + CSS + JavaScript (프레임워크·빌드 없음) |
| Backend | FastAPI (Python) |
| DB | SQLite (파일 1개) |
| AI | **AWS Bedrock Claude** — 판결문 "이유" 산문 생성 (실패 시 템플릿 폴백) |
| 배포 | AWS EC2 + nohup (포트 8501) |
| 개발 도구 | **AWS Kiro** — 팀이 작성한 설계 문서(docs/)를 기준으로 구현 |

## 빠른 시작 (로컬)

```bash
pip install -r requirements.txt
python3 data/seed.py                                # 데모 시드 (7개월 × 유형 7종)
MOCK_AI=1 python3 -m uvicorn main:app --port 8501   # 로컬은 MOCK 모드 (AWS 자격증명 불필요)
```

→ http://localhost:8501 (화면) / http://localhost:8501/api/analysis?month=2026-08 (분석 API)

시드는 월별로 다른 소비 유형이 나오도록 설계돼 있습니다 — 월만 바꾸면 유형 7종을 전부 볼 수 있어요:
`2026-08` 배달앱형 · `2026-07` 티끌 과소비형 · `2026-06` 야무진 자취생형 · `2026-05` 균형 생존형 · `2026-04` 편의점형 · `2026-03` 소확행형 · `2026-02` 취향 진심형

## 프로젝트 구조

```
main.py               FastAPI 엔트리 (라우터 → 정적 서빙 순서)
db.py                 SQLite 연결·초기화
routes/expenses.py    소비 CRUD API
routes/analysis.py    분석 통합 API (통계→판정→판결문→MZ)
services/             분석·판정 룰·판결문 템플릿·Bedrock·MZ 데이터
static/               프론트 (HTML/CSS/JS)
data/seed.py          데모 시드 스크립트
docs/                 팀이 직접 작성한 설계 문서 (00 스택 ~ 06 작업 명세)
.kiro/steering/       Kiro 자동 주입 제약 (스택·포트·리전 규칙)
```

## 판정 룰 (요약)

우선순위 순서로 첫 매칭 (전부 결정적 룰 — AI 판정 없음, AI는 판결문 산문만):
티끌 과소비형 → 편의점이 내 부엌형 → 냉장고보다 배달앱형 → 소확행 충전형 → 취향에 진심형 → 야무진 자취생형 → 균형 생존형(폴백). 수치는 [docs/04](docs/04-판정룰표.md).
