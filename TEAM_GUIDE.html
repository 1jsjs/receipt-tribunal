팀용 AWS 인프라 구축 및 Kiro 연동 가이드

AI 해커톤 참가 팀이 AWS 콘솔에서 직접 인프라(VPC → EC2)를 구축하고, Kiro에게 서버 접속 정보를 넘겨 코드를 올리기까지의 전체 과정을 담은 가이드입니다.

이 가이드에서 제공하는 코드에 대해

여기서 넘겨드리는 RAG 챗봇 코드(app.py 등 5개 파일)는 인프라와 Kiro 연동이 정상 동작하는지 확인하기 위한 예시/테스트 코드입니다. 실제 해커톤에서는 이 코드를 그대로 쓰는 게 아니라, 본인 팀의 주제에 맞게 Kiro에게 소스 코드 자체를 새로 작성하거나 대폭 수정하도록 시켜야 합니다.

이 가이드가 실제로 안내하는 건 특정 소스 코드가 아니라, "인프라를 만들고 → 서버에 인스턴스 프로파일을 붙이고 → pem 키로 Kiro에게 서버를 넘겨서 → Kiro가 코드를 개발/배포하게 하는" 전체 개발 흐름입니다. 이 흐름만 그대로 따라가면, 그 위에서 어떤 주제의 서비스를 만들든 동일하게 적용됩니다.

싱가포르(ap-southeast-1)팀 참고: 예시 코드가 쓰는 임베딩 모델(Titan Embed v2)이 싱가포르 리전엔 없습니다. RAG류 서비스를 만든다면 Kiro에게 "이 리전에서 쓸 수 있는 Bedrock 임베딩 모델을 확인하고 코드에 맞춰줘"라고 요청하세요(예: cohere.embed-multilingual-v3).

시작 전 필수 확인 사항

주의
  1. 배포받은 엑셀 파일(hackathon_team_accounts.xlsx)에서 본인 팀의 로그인 ID / 초기 비밀번호 / 배정 리전 / S3 버킷 이름 접두사를 확인합니다.
  2. 로그인 URL로 접속 → IAM 로그인 ID와 초기 비밀번호 입력 → 최초 로그인 시 비밀번호 변경이 강제됩니다. 새 비밀번호를 팀원끼리 공유해두세요(계정은 팀당 1개, 팀원 전체가 이 계정을 함께 씁니다).
  3. 로그인 직후 우측 상단 리전 선택 메뉴를 클릭해서, 엑셀에 적힌 본인 팀 배정 리전으로 정확히 변경합니다.
    다른 리전으로는 아예 접근이 차단되어 있습니다. VPC/EC2 화면 자체가 "권한 없음" 오류를 낼 수 있으니, 뭔가 안 될 때는 가장 먼저 리전부터 다시 확인하세요.

Part 1. VPC 콘솔에서 네트워크 직접 구성하기

VPC 자체가 없는 빈 상태에서 시작합니다. 아래 순서대로 하나씩 만듭니다.

1. VPC 생성

  • 이동: VPC 콘솔 → VPC 생성 클릭
  • 생성할 리소스: VPC만 선택 (또는 "VPC 등"으로 서브넷까지 한 번에 만들어주는 마법사를 써도 되지만, 아래 단계를 직접 따라 하며 구조를 이해하는 걸 권장합니다)
  • 이름 태그: hackathon-{팀ID}-vpc (예: hackathon-e1-t01-vpc)
  • IPv4 CIDR 블록: 10.0.0.0/16 (팀마다 독립된 리전에서 작업하므로 다른 팀과 CIDR이 겹쳐도 문제없습니다)
  • 완료: VPC 생성 클릭

2. 서브넷(Subnet) 생성

  • 이동: VPC 콘솔 좌측 메뉴 → 서브넷 (Subnets) → 서브넷 생성
  • VPC ID: 방금 만든 hackathon-{팀ID}-vpc 선택
  • 서브넷 이름: hackathon-{팀ID}-subnet
  • 가용 영역(AZ): 배정된 리전의 a 존 선택 (예: 서울이면 ap-northeast-2a)
  • IPv4 CIDR 블록: 10.0.1.0/24
  • 완료: 서브넷 생성 클릭

3. 인터넷 게이트웨이(IGW) 생성 및 연결

  • 이동: 인터넷 게이트웨이 → 인터넷 게이트웨이 생성
  • 이름 태그: hackathon-{팀ID}-igw 입력 후 생성
  • VPC 연결: 생성 완료 후 작업 → VPC에 연결 → 본인 팀 VPC 지정 후 연결

4. 라우팅 테이블(Route Table) 설정

  • 이동: 라우팅 테이블 → 라우팅 테이블 생성
  • 이름: hackathon-{팀ID}-rt, VPC는 본인 팀 VPC 선택 후 생성
  • 경로 편집: 생성된 라우팅 테이블 → 라우팅 탭 → 라우팅 편집
    • 대상(Destination): 0.0.0.0/0
    • 대상(Target): 인터넷 게이트웨이 → 방금 만든 IGW 선택
    • 저장
  • 서브넷 연결: 서브넷 연결 탭 → 서브넷 연결 편집 → 본인 서브넷 선택 후 저장

5. 보안 그룹(Security Group) 설정

  • 이동: 보안 그룹 → 보안 그룹 생성
  • 이름: hackathon-{팀ID}-sg, VPC는 본인 팀 VPC 선택
  • 인바운드 규칙 추가:
유형포트 범위소스설명
SSH220.0.0.0/0원격 터미널
사용자 지정 TCP85010.0.0.0/0Streamlit 웹서버용
HTTP800.0.0.0/0기본 웹 포트
HTTPS4430.0.0.0/0보안 웹 포트

완료: 보안 그룹 생성 클릭

Part 2. EC2 인스턴스 생성

1. 인스턴스 시작

  • 이동: EC2 콘솔 → 인스턴스 시작
  • 이름: hackathon-{팀ID}-server
  • OS 이미지(AMI): Ubuntu → Ubuntu Server 24.04 LTS (HVM), SSD Volume Type
  • 인스턴스 유형: 자유 선택 (사양 제한 없음 — 프로젝트에 필요한 만큼 고르되, 비용은 본인 팀이 쓰는 만큼 계정 전체에 반영됩니다)
  • 키 페어: 새 키 페어 생성 → 이름 hackathon-{팀ID}-key → .pem 다운로드 후 안전하게 보관 (이 파일이 Kiro에게 전달할 접속 키입니다)

2. 네트워크 설정

  • 네트워크 설정 우측 편집 클릭
  • VPC: Part 1에서 만든 hackathon-{팀ID}-vpc 선택
  • 서브넷: hackathon-{팀ID}-subnet 선택
  • 퍼블릭 IP 자동 할당: 활성화
  • 방화벽(보안 그룹): 기존 보안 그룹 선택 → hackathon-{팀ID}-sg 선택

3. IAM 인스턴스 프로파일 연결

가장 중요한 단계

디스크 설정은 기본 8GB에서 20GB 이상, gp3 타입 권장. 고급 세부 정보를 펼치고 IAM 인스턴스 프로파일 드롭다운에서 hackathon-{팀ID}-ec2-profile을 선택합니다.

드롭다운에는 다른 팀 프로파일 이름도 함께 보이는데, 본인 팀 것이 아니면 선택해도 인스턴스 시작 자체가 거부됩니다. 반드시 본인 팀 ID가 들어간 프로파일만 선택하세요.

시작: 인스턴스 시작 클릭 → 부팅 완료 후 퍼블릭 IPv4 주소 복사

Part 3. Kiro에게 서버 넘기기

1. 로컬에 프로젝트 폴더 하나로 모으기

본인 PC에 폴더를 하나 만들고(예: {팀ID}-project), 아래 파일들을 전부 그 안에 넣습니다.

  • 방금 다운로드한 hackathon-{팀ID}-key.pem
  • 실습 코드 5개: app.py, bedrock_simple_test.py, bedrock_faiss_indexer.py, bedrock_faiss_rag_chatbot.py, requirements.txt

그 다음 Kiro에서 이 폴더를 프로젝트 폴더로 지정합니다(Kiro가 파일을 열람/수정할 작업 폴더로 인식하게). pem 키와 소스 코드가 한 곳에 있어야 Kiro가 접속 정보와 올릴 코드를 헷갈리지 않고, 이후 코드를 고칠 때도 이 폴더의 파일을 수정 → 서버에 반영하는 식으로 계속 재사용할 수 있습니다.

2. 최초 빌드 요청

EC2의 퍼블릭 IP 주소를 확인한 뒤, Kiro에게 다음 내용을 포함해서 요청하세요(그대로 복사해서 써도 됩니다):

이 프로젝트 폴더에 있는 pem 키로 아래 EC2 서버에 SSH 접속해서 초기 환경을 세팅하고, 폴더 안의 RAG 챗봇 코드를 올려줘.

- 접속: ssh -i hackathon-{팀ID}-key.pem ubuntu@{퍼블릭IP}

- AWS CLI 설치, pip3 install -r requirements.txt로 파이썬 패키지 설치 (구버전 pip는 --break-system-packages 옵션이 없어서 에러가 날 수 있으니, 에러가 나면 옵션 없이 그냥 재시도해줘)

- S3 버킷을 새로 만들어야 하는데, 반드시 hackathon-{팀ID}-로 시작하는 이름으로 만들어줘(예: hackathon-{팀ID}-docs). 이 규칙을 안 지키면 권한 오류(AccessDenied)가 난다.

- 코드 안의 BUCKET_NAME 값을 방금 만든 버킷 이름으로 바꿔줘. 그리고 이 값을 로컬 프로젝트 폴더의 파일에도 그대로 반영해서, 다음에 코드를 다시 올릴 때 값이 안 사라지게 해줘.

- Bedrock 클라이언트를 만들 때 region_name을 절대 직접 지정하지 마(특히 us-east-1). 리전은 EC2가 있는 곳을 자동으로 따라가야 하고, 배정된 리전 외에는 IAM이 전부 막혀 있어서 다른 리전을 넣으면 100% AccessDenied가 난다.

- Claude 모델을 호출할 때는 반드시 global.anthropic.claude-sonnet-5 형태의 추론 프로파일 ID를 써야 해(코드에 이미 이렇게 돼 있으면 그대로 두면 됨). anthropic.claude-sonnet-5처럼 앞에 global.이 없는 raw 모델 ID로 부르면 "on-demand throughput isn't supported" 에러가 난다.

- 이후 Streamlit(app.py)을 nohup으로 백그라운드 실행해서 8501 포트로 띄워줘. pip로 설치한 실행파일이 PATH에 없을 수 있으니 streamlit 명령 대신 python3 -m streamlit run app.py --server.address 0.0.0.0 형태로 실행하고, SSH 세션이 안 끊기고 멈추면 nohup ... > streamlit.log 2>&1 < /dev/null & 형태로 표준입력까지 분리해줘.

  1. Kiro가 작업을 마치면 http://{퍼블릭IP}:8501로 접속해서 RAG 챗봇이 뜨는지 확인합니다.
  2. 이후 기능 추가나 코드 수정도 계속 Kiro에게 맡기면 됩니다 — EC2 서버 안에서는 인스턴스 프로파일 덕분에 API 키 입력 없이 S3/Bedrock을 바로 쓸 수 있습니다.

3. 이후에 코드를 다시 수정/재배포할 때

주의 — 값이 초기화되지 않게

프로젝트 폴더 안의 파일을 고쳐서 Kiro에게 "이 파일들로 서버 업데이트해줘"라고 할 때, BUCKET_NAME 같이 서버에 이미 반영된 실제 값을 새 코드가 플레이스홀더나 옛날 값으로 덮어쓰지 않는지 먼저 확인하도록 시키세요. 새 기능 코드만 바뀌어야 하는데 버킷명 같은 설정값까지 초기화되면, 이미 만들어둔 버킷/인덱스와 안 맞아서 AccessDenied가 납니다. Kiro에게 "서버에 이미 반영된 BUCKET_NAME 값을 확인하고 그대로 유지한 채로 나머지 코드만 반영해줘"라고 명시하면 안전합니다.

4. Claude 말고 다른 모델(GPT 등)을 쓰고 싶을 때

Bedrock에는 Claude 외에 GPT, Grok 같은 다른 회사 모델도 같이 올라와 있습니다. 아래 표에 있는 모델은 팀 권한으로 바로 호출 가능합니다.

제공사사용 가능 모델모델 ID 예시
AnthropicClaude Sonnet, Claude Haikuglobal.anthropic.claude-sonnet-5
OpenAIGPT-5.6 Sol, GPT-5.6 Lunaglobal.openai.gpt-5.6-sol

위 표는 대화/텍스트 생성용 모델 기준입니다. RAG 챗봇처럼 임베딩(문서 검색용) 모델은 별도로 계속 허용되어 있습니다 — amazon.titan-embed-text-v2:0, cohere.embed-multilingual-v3 등. 예시 코드(bedrock_faiss_indexer.py 등)가 이미 이 방식으로 되어 있으니 그대로 쓰면 됩니다.

막혀 있는 모델

Claude Opus, Claude Fable, GPT-5.6 Terra, Grok은 비용이 높아서 팀 권한으로 호출이 명시적으로 차단(AccessDenied)되어 있습니다. Kiro가 실수로 이 모델 이름을 코드에 넣어도 어차피 호출 시점에 거부됩니다.

주의: Claude와 GPT는 같은 Bedrock invoke_model API를 쓰지만, 요청/응답 형식(포맷) 자체가 다릅니다. 모델 ID만 바꾼다고 되는 게 아니라 코드도 같이 바꿔야 합니다.

Claude (Anthropic)GPT (OpenAI)
요청 바디{"anthropic_version": "...", "max_tokens": N, "messages": [...]}{"messages": [...], "max_completion_tokens": N}
응답 파싱response["content"][0]["text"]response["choices"][0]["message"]["content"]

그래서 모델을 바꾸고 싶으면 Kiro에게 이렇게 구체적으로 요청하세요(모델 ID만 알려주면 요청 형식은 그대로 두고 ID만 바꿔서 에러가 날 수 있습니다):

지금 Bedrock 호출 코드를 Claude(global.anthropic.claude-sonnet-5) 대신 GPT(global.openai.gpt-5.6-sol)로 바꿔줘. GPT는 OpenAI Chat Completions 포맷이라 요청 바디는 messages + max_completion_tokens로 만들고, 응답은 response['choices'][0]['message']['content']로 파싱해야 해.

하면 안 되는 것 / 해도 안 되는 것

  • 다른 리전 접근: 배정된 리전 외에는 VPC/EC2 관련 작업이 전부 막혀 있습니다.
  • 다른 팀 인스턴스 프로파일 사용: PassRole 권한이 자기 팀 프로파일에만 있어서, EC2 시작 자체가 거부됩니다.
  • 접두사 없는 S3 버킷 생성: hackathon-{팀ID}-로 시작하지 않는 이름은 생성이 거부됩니다. 마찬가지로 다른 팀 버킷이나 계정에 원래 있던 일부 버킷도 접근이 막혀 있습니다.
  • Access Key 발급/사용: 필요 없습니다. EC2 인스턴스 프로파일이 자동으로 인증을 처리하므로 Access Key를 따로 만들 필요가 없고, 만들 수 있는 권한도 없습니다.
  • 고사양 모델 호출: Claude Opus/Fable, GPT-5.6 Terra, Grok은 비용 문제로 차단되어 있어 호출 시 AccessDenied가 납니다.
문제가 생겼을 때

가장 먼저 다음 세 가지부터 확인하세요. 대부분의 오류는 이 중 하나입니다.

  1. 리전이 맞는지
  2. IAM 인스턴스 프로파일 이름에 본인 팀 ID가 들어갔는지
  3. S3 버킷 이름이 접두사 규칙을 지켰는지
